# Glossary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a dopamine project a `GLOSSARY.md` that agents grep instead of reading code, and prove with GREEN that it saves cost before the upkeep is built.

**Architecture:** The `SessionStart` hook appends one pointer sentence when `glossary:` is declared and the file exists. A shipped script checks each entry's `→ path:symbol` pointer. GREEN reruns RED's seven questions under a control arm C and a glossary arm G. Only if G passes do the schema, routing, sweep and adoption changes get built.

**Tech Stack:** bash (hook, scripts, tests via `tests/helpers.sh`), python3 (baseline `score`), Markdown skills, `claude -p` for baseline runs.

**Spec:** `docs/superpowers/specs/2026-11-02-glossary-design.md`

## Global Constraints

- **Pointer sentence**, verbatim, with the declared path in place of `docs/GLOSSARY.md`:
  "This project's own terms are defined one per line in `docs/GLOSSARY.md`. When you meet a term whose meaning you need, search that file for it with the Grep tool before reading code to work it out."
- **The hook's context file:**
  - It stays within 240 words.
  - It contains no `never`, `do not` or `don't` (both enforced by `tests/hooks/test-session-start.sh`).
- **Word budgets in `tests/skills/test-skill-structure.sh`.** A budget is raised only with a comment in its BUDGETS block that says why and ends "Not licence to pad." These are the maximum new budgets:

  | Skill | New budget, at most |
  |---|---|
  | `routing-documentation-updates` | 660 |
  | `finishing-work` | 880 |
  | `adopting-a-repo` | 950 |

  Set each one to the measured count, rounded up to the next 10.
- **Fixed records:**
  - `tests/baselines/glossary/fixture/` is not changed, so RED stays reproducible.
  - RED's `red/score.md` is not touched.
  - Specs, plans and sealed ledgers are immutable.
- **Baseline runs:**
  - They use the subscription login through `run-task`'s empty config dir, never `--bare` or an API key.
  - The model is Sonnet (`BASELINE_MODEL` default).
- **No `gls-global` content** goes in any file.
- **Comments** follow `dopamine:writing-code-comments`: a why, a contract or a warning.
- **`PROGRAM-DESIGN.md` is declared but absent.** This plan was written without its rules; the human was asked once at hand-off.

## Review Focus

1. **A config line with trailing spaces or CRLF** (`glossary: docs/GLOSSARY.md\r`): the hook still finds the file and the sentence carries the clean path. The test is in Task 2.
2. **`glossary:` declared twice:** the first line wins and only one sentence is emitted. The test is in Task 2.
3. **A glossary entry with no `→` pointer:** `check-glossary-pointers` reports it as dead rather than skipping it. The test is in Task 1.
4. **A glossary written with CRLF line endings:** pointers still resolve. The test is in Task 1.
5. **A pointer whose path has directories** (`leadflow/portal/visibility.py:_suppress_score`): the split is on the *last* colon, and every path is resolved against ROOT, not the current directory. Task 1's test runs the script from another directory.

### Task 1: Pointer-check script

**Files:**
- Create: `skills/finishing-work/scripts/check-glossary-pointers`
- Create: `tests/scripts/test-check-glossary-pointers.sh`

**Interfaces:**
- Produces: `check-glossary-pointers GLOSSARY ROOT`.
  - **Entries:** every line starting `- **` is one. Its headword is the text between the first `**` pair.
  - **Pointer:** the last `` → `path:symbol` `` on the line, split on the last `:`.
  - **Resolves:** the pointer resolves when `ROOT/path` is a file containing `symbol` (fixed string).
  - **Output:** one line per failure, `dead: <headword>: <path:symbol> (no file)`, `(no symbol)` or `no pointer: <headword>`.
  - **Exit codes:**

    | Exit | Meaning |
    |---|---|
    | 0 | all resolve |
    | 1 | any failure |
    | 2 | usage, or GLOSSARY missing |

- [ ] **Step 1: Write the failing test.** Build a temp `ROOT` with `a/b.py` holding `def real():`, then assert:

```bash
# glossary with a title line, a header sentence and one resolving entry
assert_exit "all pointers resolve" 0 bash "$UNDER_TEST" "$G" "$ROOT"
assert_eq "and nothing is printed" "" "$(bash "$UNDER_TEST" "$G" "$ROOT")"
# + "- **gone** — x → \`a/missing.py:real\`"
assert_contains "a missing file is dead" "$out" "dead: gone: a/missing.py:real (no file)"
# + "- **moved** — x → \`a/b.py:renamed\`"
assert_contains "a missing symbol is dead" "$out" "dead: moved: a/b.py:renamed (no symbol)"
# + "- **bare** — no pointer here"
assert_contains "an entry without a pointer is reported" "$out" "no pointer: bare"
assert_exit "any failure exits 1" 1 bash "$UNDER_TEST" "$G" "$ROOT"
# the resolving glossary rewritten with CRLF endings
assert_exit "CRLF line endings resolve" 0 bash "$UNDER_TEST" "$CRLF" "$ROOT"
assert_exit "paths resolve against ROOT, not the cwd" 0 \
    bash -c 'cd / && bash "$0" "$1" "$2"' "$UNDER_TEST" "$G" "$ROOT"
assert_exit "no arguments exits 2" 2 bash "$UNDER_TEST"
assert_exit "a missing glossary exits 2" 2 bash "$UNDER_TEST" "$ROOT/none.md" "$ROOT"
```

- [ ] **Step 2: Run it and check it fails.** Run `bash tests/scripts/test-check-glossary-pointers.sh`. Expected: FAIL, script not found.
- [ ] **Step 3: Implement the script** in bash, with a header comment giving usage and exit codes, as `refresh-rule-card` does. Strip `\r` before parsing.
- [ ] **Step 4: Run the test and check it passes.** Expected: all `[PASS]`.
- [ ] **Step 5: Commit.** Run `git add skills/finishing-work/scripts tests/scripts/test-check-glossary-pointers.sh`, then `git commit -m "feat: check-glossary-pointers reports dead glossary pointers"`.
